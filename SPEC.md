# Current behavior and acceptance

## Catalog

The configured CCSH/IPTV `live_lite.m3u` and `others.txt`, plus all unique HTTP(S) directory URLs in the TVAPP README live-source section, are fetched server-side. The README is fetched at runtime; only its live-source section is interpreted as data, never the application/configuration sections. Each directory content is parsed as M3U (#EXTM3U/#EXTINF) or TXT (name,url / #genre#), including overseas and IPv6 sources. Catalogs merge by a channel identity that ignores quality-only markers, recognized leading country tags, ASCII letter case and whitespace; exact duplicate playback URLs are removed. Display names retain a clean representative spelling, preferring the canonical uppercase spelling when present. Quality and country metadata from source names are retained per URL and unioned when duplicate URLs appear. Country-only variants merge by the same base identity; an unmatched country label remains in the display name, while matching unlabeled or differently country-tagged variants use the clean name. Country metadata still supports Japanese shortcut matching. Time-shift suffixes and region words inside station names remain distinct. Each directory retains its last valid response; partial failures use that cache and show a partial-update notice. Base CCSH inputs must remain available before replacing the merged catalog. Downloads use three workers, serialize each host and add 0.7–1.3-second spacing after three requests. Network failures, 403/429 or 5xx stop further requests to that host for the refresh. Missing 404 files are recorded separately. Directory requests do not test stream playback. D1 payloads are gzip/base64 encoded. Large payloads split into rows of at most 1,000,000 characters; chunk rows and the root manifest commit in one D1 transaction. Old chunks remain for one day so in-flight readers can finish. Initial requests return the existing server catalog immediately. A cold cache loads only the two CCSH directories first; the browser accepts those channels and starts playback before requesting the full TVAPP merge in the background. Existing full catalogs refresh in the background after one hour. The catalog API returns refreshNeeded for this second phase, using separate base/full refresh leases. Background merging preserves current playback. If another visitor owns a refresh, the client polls only the lightweight synchronization timestamp every 15 seconds (up to two minutes), then retrieves the completed catalog; it does not restart upstream directory downloads. “更新目录” requests a real GitHub refresh, limited to once per minute; the response identifies a new GitHub fetch versus cache. No predownloaded catalog or verification result is bundled. First load must succeed against the runtime API or display a genuine empty/error state. Failed, empty, invalid or suspiciously truncated updates retain the previous catalog. HTTP HLS sources are supported through the site relay. There is no server-side source deletion based on reachability; legacy Flash and direct MP4/audio files remain visible but are not attempted.

CCTV5 and CCTV5+ are separate. Source identity is the complete URL, never array position. A sorted SHA-256 digest identifies the catalog version. New URLs invalidate channel-level unavailable records without deleting unrelated history.

## Playback

Non-native HLS sources first receive an HTTP GET (same-origin relay for HTTP sources, direct CORS request for HTTPS) with a 6-second direct-source timeout or 45-second HTTP relay timeout. Response-header latency is displayed; HTTP failure or a network/CORS rejection stops that attempt before media validation. This is browser HTTP reachability, not ICMP ping; a CORS failure does not prove an offline upstream. Native HLS assigns the video URL and attempts inline playback immediately; a CORS fetch failure cannot block native media playback. Manifest inspection runs alongside playback and can use the catalog-authorized HTTPS relay when direct inspection fails. Confirmed ended/VOD lists still reject; one unchanged live-list sample is inconclusive. Native inspection allows up to three target-duration reloads within the existing timeout; a later advancement verifies normally, while three valid live manifests with no advancement fail with an explicit fixed/stale-playlist reason. Network/inspection errors remain inconclusive, not proof of a dead stream. Advancing video with inaccessible or inconclusive manifests remains playing as unconfirmed, does not report success/failure solely for inspection failure and does not write a verified preference.

Browser HLS (hls.js or native) verifies actual advancing video for at least two seconds with positive video dimensions and, when supported, frame callbacks. Manifest success and audio-only streams are insufficient. Direct video files are excluded. HLS ENDLIST/VOD playlists are rejected. hls.js requires a live playlist whose media sequence advances across reloads. Native HLS inspects the media manifest (one master traversal), checks for sequence/segment advancement across bounded target-duration reloads while playback starts immediately. Inaccessible or unconfirmed manifests never become verified live sources, but actual native video frames may remain visible with unknown live status. A live playlist still does not prove broadcaster identity or real-time program authenticity. The current source begins rendering before full verification. Status and history become successful only after verification.

The first candidate has a 30-second active-time budget for direct HTTPS or 90 seconds for HTTP relay (including evidence of playlist advancement); current playback gets a 12-second stall window, one recovery opportunity, then another window before failover. Each source is attempted at most once per channel connection cycle. Initial source discovery is automatic regardless of the automatic-recovery toggle; after verified playback the toggle controls switching. A user action can restart a cycle and reset that channel's cooldowns. No endless A/B cycling.

Autoplay denial prompts for one click. Pause, cancellation, hidden pages and offline state do not record failures. On PC, one muted verification player checks all remaining sources of the selected channel, after foreground connection attempts settle. Mobile devices (including touch iPads with desktop user agents) never start hidden playback probes: the foreground player connects one candidate at a time and stops trying others once playback succeeds. Mobile failure fallback waits 1.5 seconds and does not advance while hidden/offline. Explicit source selection/recheck and recovery remain available. It never scans other channels. Results are scoped to a selection/recheck cycle and include waiting, connectivity checking, live verification, verified, failed, gesture-blocked and unsupported. The foreground and probe share results, avoid duplicate simultaneous tests, and process each remaining source once. Checks are staggered 1.2–2 seconds; changing channel cancels the prior queue. Hidden/offline pages suspend it without failed-source penalties. Manual source choice tries that source first (even during cooldown), then follows normal fallback. Recheck resets the current channel cycle. Unsupported file sources remain visible with an explanation but are not requested.

## Local state

IndexedDB stores catalog, source health, favorites, last successful channel, recent successful channels (20), and auto-switch preference. Each channel stores its last foreground source that passed actual live playback verification, without expiry. This source is attempted first once per connection cycle while still present in the compatible catalog, even if an old cooldown exists. Explicit manual selection precedes this preference; failure falls back normally. Background verification never changes this per-channel preference. Successful local records do not expire by age; one local failure immediately invalidates local availability until success. backup freshness 10 minutes; Failure cooldown: 10, 30, then 120 minutes. Channels without browser-compatible candidates wait 6 hours or a catalog change. Default browsing displays failed channels and sources. The device-local display preference has three modes: 全部 keeps the existing order and all entries; 优先可播源 places current-device applicable recent success, older success, then possible hints ahead of other channels, retaining the existing category/source-count/recent order within each tier; 不显示失效源 on PC hides PC instability only; on mobile it hides either PC or mobile instability, even if the other device succeeds. A current local result overrides only its own device report. 网页直连受限 sources are also hidden in this mode, even if historical successes exist. Unknown evaluations remain visible. Channels with no remaining visible source are hidden using the same predicate, including unsupported-only channels. This filtering is independent of display ranking and automatic-attempt order. Legacy hideFailed=true migrates to 不显示失效源; false/absent migrates to 全部. Both playable views also admit channels with a current-device possible hint; no inferred verification is saved. 本机可播 retains actual foreground viewing order, with unviewed hinted channels last under 全部. Storage failure keeps this session usable and displays a notice.

## Interface and access

Chinese dark working surface, responsive desktop/mobile. The workspace fills the viewport width without a desktop max-width cap; sidebars retain their readable widths while the player column expands. Desktop sidebar stretches to the main column height, with its channel list filling the remaining space rather than a viewport-height cap; its contents do not force the page taller. Mobile uses single-column channel rows with two-line name/status content, page scrolling instead of a nested scroll pane, compact playback settings, and batches of 80 channel rows for the large merged catalog. The 全部 category (outside search) sorts by descending deduplicated source count, using the existing name comparator for ties; other category and recent/favorite ordering remain unchanged. 本机可播 always puts previously watched channels first in descending actual foreground playback time, followed by possible-playback channels without viewing history; availability-priority mode does not override this order. Background probe success time is not viewing time. Older saved data falls back to its recent-channel order, with unknown viewing times last. Default channel lists show channels with at least three catalog sources. Phoenix channels in 港澳台 and Bloomberg/彭博, CNBC, CNN, BBC and Japanese channels in 海外 are exempt from this count; CCTV, satellite/local priority are not. Names beginning with Unicode punctuation or symbols (after leading whitespace, except [ and 「) are deferred. These two opening brackets are exempt regardless of their following text; source-count rules still apply. “更多” reveals deferred channels after primary entries, preserving existing order within each group and 80-row pagination. Search matches and both playable views bypass both deferral rules, while existing hide-failed and tab filters still apply. Query/tab/category/display-mode changes reset expansion. Search ignores current category to find all matching channels. The source selector displays up to 20 lines per page, preserving per-channel source numbers after health ordering/filtering/pagination and independent all-source checking. Changing channels resets to page one; a locate-current action can show a playing line on another page. Compact cards retain the source number, current line, connection mode tooltip, response latency, progress and failure reason. The channel source label covers its entire card as one radio target, including whitespace/status/latency; disabled radios remain disabled and keyboard selection is retained. Normal cards use two compact rows: number/catalog-quality-and-country badges/current marker/latency/status, then hostname/IP and PC/mobile evaluations; only a failure reason adds another row. Quality badges (such as 1080p, VGA, 720p) omit brackets and reflect catalog metadata, not measured playback resolution; unlabeled sources get no inferred badge. Only the hostname/IP is exposed, without scheme, port, path or query. Original URLs, copy-address and open-original controls are not rendered in the interface. URLs remain internal source identities. HTTP sources remain selectable with HTTPS 转发 in the latency tooltip. The footer keeps synchronization time, a brief no-recording note and directory notices, without repository links or raw input filenames. The manual update action is hidden by default on the deployed site; NEXT_PUBLIC_SHOW_CATALOG_REFRESH=true enables it at build time for self-hosted deployments. Automatic refresh remains active. The desktop channel scrollbar is thin, rounded and low contrast. No fabricated program schedule or stream rankings. Official CCTV links are fallback navigation and do not guarantee overseas viewing. Site sharing is public by explicit user instruction; no app authentication.

“换个频道看看” uses compact single-column cards in the right connection sidebar; at narrow widths that sidebar follows the player/source area.

WebMCP: `search_channels` is read-only; `start_channel_playback` starts the same visible connection action and reports attempt status. Unknown IDs fail without changing state.

## Channel links

`?channel=<c-prefixed UTF-8 hex of canonical channel identity>&source=<optional positive integer>` selects a channel and optionally its persistent source number, never a sorted array position or arbitrary media URL. The generated channel key is a deterministic, reversible byte encoding containing only c/0–9/a–f, without hash truncation/collisions between distinct valid Unicode identity strings. Intentional quality/case/whitespace equivalences are merged before encoding. URLSearchParams handles parameter serialization, and legacy URL-encoded names (including +, &, #, quotes and Unicode) remain accepted; no parameter is evaluated as code/HTML or used as a redirect target. CCTV5 and CCTV5+ remain distinct. Parameters resolve via the same canonical identity as catalog merging; old quality/case/whitespace name variants still find the merged channel. Other renames remain new channels. An unresolved target waits for the initial base/expanded catalog cycle to settle before reporting a missing channel/source and falling back. Manual user selection cancels initial-link intent. Successful initial selection updates the category; channel/source changes update the same-page address bar with properly encoded values. Existing automatic recovery and gesture requirements remain.

## Acceptance

Verify compilation, catalog merging/version stability/rejection, cooldown ordering, automatic first-source failure fallback, genuine-frame success, pause/offline cancellation, favorites persistence, UI empty states, WebMCP valid/invalid actions and responsive layout. Live CCTV5+ playback requires at least one working direct HTTPS or relayed HTTP HLS source; a test video or another channel does not fulfill that requirement.

## Categories

Category buttons are 央视、卫视、地方、港台、日本、海外、其他、全部, followed by 本机可播、他人可播 as compact naturally wrapping buttons. 港台 is the display label for the existing 港澳台 group and still includes Macau. 日本 is a shortcut over matching 海外 channels; they remain visible in 海外. Within category browsing, 港澳台 prioritizes names containing 凤凰; 卫视 prioritizes 北京, 上海/东方, 湖南, 浙江 in that order; 地方 prioritizes names containing 北京; 海外 prioritizes Bloomberg/彭博, CNBC, CNN, BBC in that order, without a separate Japanese pin. The Japanese shortcut matches 日本, 日语, NHK, a leading JP country tag, kana characters or the existing known Japanese station-name patterns (TOKYOMX, TVTOKYO, WOWOW, TBS, BS11, BS12). This is a name heuristic within 海外, not a verified origin/language attribute. Within 日本 only, names beginning with Latin letters or Japanese kana rank before other names, ignoring leading quality and JP country tags and normalizing full-width characters for this comparison only. Remaining names retain the standard ordering. Search/all/favorites are not reordered by these category pins. The three-mode preference can overlay availability tiers; within a tier, the original order is retained. Local means terrestrial local/provincial/city channels, excluding satellite channels. Use catalog group and recognizable name prefixes; uncertain entries go to 其他. Phoenix TV matches specific channel names rather than all 凤凰 prefixes; 凤凰传奇 belongs to 其他, overriding obsolete cached 港澳台 groups. Classification is best effort; no external per-channel lookup. Local-name recognition uses a bundled mainland dictionary of 31 province-level groups and 333 prefecture-level units (cities, autonomous prefectures, prefectures and leagues), including full names/common short names and 32 province-administered county units. A small explicit station alias list covers existing county examples. Dictionary baseline: 2023-06-30, derived from [Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China/tree/c49d495b40ac73eb1a66f6eeae5f8fd10696f035), WTFPL; this is a name-matching baseline, not a live register. Names starting with these places classify as 地方 or 卫视 before stale imported group hints; country markers and 港台 routing remain separate. Leading bracketed quality tags (HD/FHD/UHD/SD/VGA, common resolution tags and Chinese quality labels) are ignored for classification and category priority; catalog normalization also extracts them into source quality labels. A recognized station name overrides stale imported grouping; country tags remain source metadata and unmatched display hints, but do not prevent merging otherwise identical station names. Quality markers are removed from channel display names and moved to source metadata; channel identities ignore these markers, ASCII case and whitespace. Cached client/server catalogs are merged and reclassified on read, and the health API resolves the same canonical channel identities. ## HTTP HLS relay

`/api/stream` accepts an exact source in the server catalog as a root playlist. Redirects are followed manually (up to five), relative paths resolve against the final URL, and variant/audio playlists, segments, keys, maps and partial segments receive same-origin signed URLs. Descendant tickets bind the URL, resource kind and 24-hour expiry with HMAC; a runtime-generated key is kept in D1's internal `relay-signing-v1` row and never returned to clients. Unknown roots, forged tickets, credentials in URLs, private/local targets and non-HTTP protocols are rejected. DNS answers are checked for public addresses before upstream requests. Client cookies and authorization are never forwarded.

Manifests have a 2 MB limit. Media bytes stream through without storage, recording or transcoding. Range requests and partial-response headers are preserved for media assets. Playlist requests ignore client Range headers, including iPhone bytes=0-1 probes, and fetch/rewrite the whole playlist. Safe media MIME types are preserved; known segment extensions supply a fallback type while other assets remain application/octet-stream. Native media failures expose a diagnostic code distinguishing network, decode and unsupported-source errors. Responses are not cached, executable upstream content is not served as HTML, and upstream failures are shown in the source list. Playlist signatures changing do not count as live sequence advancement. A one-time local migration clears old HTTP relay failure cooldowns and channel exclusions while retaining favorites and successful playback records. Hosting egress, upstream access restrictions and regional restrictions still determine actual playback; source acceptance remains with the user.

Standard CCTV1–n channels sort first numerically, with CCTV5+ immediately after CCTV5. Variants and other names follow. Selection does not pin a channel ahead of this order; recent viewing retains chronological order. Standard CCTV entries remain visible with their status even when a check fails unless the user enables the hide-failed filter.

## Channel name consolidation

A single text column displays complete channel names (for example CCTV11戏曲), without a separate code/icon column. Exact standard CCTV code and known program-title aliases normalize to the same stable code ID, merge their source groups and deduplicate exact URLs. Quality-only suffixes such as (576i) are removed from CCTV names; regional variants and unrelated programs remain separate. Obvious 卫视 separator variants and the NPTV suffix normalize together. Cached catalogs and local favorites/recent IDs normalize on load; full source URLs remain stable.

Initial automatic playback waits for the first runtime catalog request to settle, so an old browser catalog cannot start relay requests before the server catalog is ready. If refreshing fails, the cached catalog remains the fallback.

HTTP IPv4 literal targets use a DNS-only sslip.io hostname for Workers compatibility. DNS answers must equal the original public IPv4 before fetching; original source identity and relative URL bases stay unchanged. HTTPS IP targets are not rewritten because certificate identity would change.

Relay connection attempts have a 35-second overall redirect deadline and a 20-second per-hop response deadline. The client allows 45 seconds for relay connectivity so multiple redirect hops can complete or return a specific hostname/hop failure.

## Shared source reports

`/api/source-health?channel=ID` returns viewer-specific PC/mobile summaries. `scope=catalog` reads only stored reports for URLs still in the catalog, without requesting streams. GET accepts X-Playback-Observer; same-origin POST requires source, status, device and a browser UUID. IndexedDB persists that random observer. D1 source_votes uses source + device + SHA-256(source + observer) as its key and stores server timestamps. Raw observer, IP, account and error strings are not stored. Browser profiles approximate distinct users; this is not authenticated identity. The viewer's own failures are excluded from shared failure quorum.

Shared success has no age expiry. Latest success protects it for 24 hours. Later failures are retained during protection, but shared success is revoked only after protection ends AND ten distinct other browsers have failed after that success. Repeated votes count once, and a newer success resets the baseline/protection. PC and mobile votes never combine. Fresh authoritative snapshots may clear a previously aggregated failure when it no longer meets the quorum, without replacing reports newer than the snapshot or changing local failures. With no success, two other failures establish shared instability. A single local failure immediately marks local instability while contributing just one vote for other viewers. Legacy device-tagged successes survive; unattributed legacy failures cannot count as a quorum. Removed URLs lose votes, shared marks and local health/preference references after valid catalog updates; failed directory updates retain their last valid content.

The shared-playable channel view includes any PC or mobile shared success and sorts like All by deduplicated source count. The local-playable view uses local success newer than local failure and sorts by last foreground playback. Both additionally include applicable 可能可播 hints and bypass the sparse/symbol deferral rules. The display-mode preference can overlay availability tiers. Neither view expires success by age.

Actual frame/live verification reports success; actual connection/playback failures report failure. Paused/offline/hidden cancellation, permission prompts, and unsupported formats do not report failures. Duplicate identical reports from one session are suppressed for one minute; a changed outcome is sent immediately. Shared-state failure never interrupts playback.

On channel selection, fetch current shared status (at most five seconds), then defer current-device instability behind other candidates; within the remaining candidates prefer locally last-watched success, other recent success, older success, same-host hints and unknown. Explicit manual selection wins. Visible/online selected channels refresh shared status every minute on PC and every five minutes on mobile. Source cards promote a valid success on either PC or mobile even when the other device is unstable. The State fusion and channel signals section defines the recent/older and inferred tiers. Automatic playback and background checks use current-device suitability independently of this display order. Labels distinguish 本机/他人, PC/mobile, recent/older success, instability and host inference. Shared hints never set local success or overwrite the user's last-watched preference. Hiding failed sources also hides shared unstable entries; unchecked sources remain. Source numbers are stored with catalog source URLs per channel. Existing numbers survive reordered imports, ranking, hiding and pagination; after a valid directory update removes a URL, new URLs use the lowest free numbers without compacting survivors. Older cached catalogs use their existing array positions for the initial allocation. When groups merge, retain the canonical group’s existing URL numbers first, then nonconflicting variant numbers; collisions receive free slots. A historical variant link with a colliding line number must be updated to the merged group’s number. Local favorites/recent history are deduplicated by canonical identity, retaining the latest viewing time and its preferred source. URL-based selection and 20-per-page pagination remain.


## Device-specific shared evaluation

Both PC and mobile raw results are displayed independently. For automatic attempts, mobile uses its own result when present; otherwise it references PC. PC preserves its own instability; otherwise it combines its own success time with mobile success time and uses only PC failure time. When one device is unknown and the other has a valid success, the unknown side borrows that recent/older tier for channel signals and display ranking, while its device label is 可能可播, a reference rather than actual verification. Thus PC success cannot override a recent mobile failure; a mobile failure never demotes PC, including after a mobile success. A PC instability result cannot be overridden for automatic attempts by mobile success; recovery requires PC success. The protection/quorum rules above determine each shared device summary. Local verified results still take precedence in local ranking. Legacy unclassified shared records are ignored, not assigned to either device; untagged old-client reports are rejected. All report tables are pruned for removed sources. One-time local playback-version migration clears pre-fix failure cooldowns, preserving favorites, successful records and viewing preferences.

A [BD] prefix is treated as a quality label when the remaining name begins with Chinese characters or identifies a known station (including CNBC/Bloomberg); otherwise its Bangladesh country meaning is retained. A generic name such as 经济科教 alone does not prove a local station; use a recognized place/name or an explicit local catalog group. Japanese classification, shortcut filtering and source-count exemption share the same matcher; BS-TBS, Tokyo MX and WOWOW are recognized without broad matching of TBS Seoul or US call signs. Japanese channels are exempt from the three-source default visibility threshold; leading-symbol deferral remains unchanged.

## State fusion and channel signals

Actual successes under 24 hours are 近期可播; at 24 hours they become 可播 with lower list priority, without expiring. This label age is separate from shared 24-hour failure protection. Local success/failure takes precedence over the same device's shared result; PC and mobile remain separate. Cards show 本机/他人 attribution and retain conflicting shared evidence beside a local result. If the current device has no local/shared result and the other device has recent/older success, the current effective status borrows that same tier for its signal and ranking. The untested device label remains 可能可播 when the other device succeeds; no verified timestamp or success report is invented. Explicit current-device instability is never replaced by this reference.

Related-host hints use the original HTTP(S) URL's registrable domain (Public Suffix List with private suffixes), ignoring subdomain, scheme and port. For example 23.xxx.com and tv.xxx.com share xxx.com; example.co.jp and other.co.jp do not merge, nor do unrelated hosted tenants. Literal IPv4/IPv6 use the full normalized IP. No DNS aliases are resolved. A real successful source still in the catalog can mark otherwise unknown sources in that domain/IP group 可能可播, preserving the device supplying the hint. Explicit current-device failure and unsupported sources cannot be overridden; same-source cross-device success stays a device reference rather than a host inference. Hints enter both 本机可播 and 他人可播 views, but never write local/shared success or propagate recursively. Recompute them when records fail, shared summaries change or the supporting URL leaves the catalog. No host probe or DNS lookup is added.

List order is recent success, older success, possible, unknown, unstable, unsupported. Either device's direct success may promote a line while the current device remains unstable. For locally unstable lines with actual shared success, display ordering retains that shared evidence: same-platform success precedes opposite-platform success, then recency within each group. These lines follow usable recent/older successes and precede possible/unknown/unsupported lines and unstable lines with no shared success. Local failure labels, channel signals and automatic attempt eligibility are not overwritten; host hints do not count as actual shared success. Numbers, source URLs, 20-line pagination and device-specific hide-failed semantics are unchanged. Automatic attempts keep a valid local last-watched preference; a persistent local failure remains behind other candidates even after its cooldown ends. Recent successes then precede older successes, host hints and unknowns. Manual choice wins. Background PC checks use the same evidence priorities without replacing foreground preference; mobile remains foreground-only.

Channel aggregation uses compatible candidates on the current device. Green means an applicable success, including a borrowed opposite-device success when the current device is unknown: bright green for recent, muted green for older. Host-only evidence gives two amber bars. Any unresolved candidate prevents an all-failed judgment; pending is gray with a hollow dot when no applicable success or hint exists. Orange slashed bars mean all attemptable candidates have explicit failure; unsupported-only and offline are gray slashed. Foreground connection/recovery pulses gray; background checks never replace an existing successful channel signal. Reduced-motion disables pulsing.
